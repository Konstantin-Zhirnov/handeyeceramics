# 0001. Hosted Stripe Checkout с price_data

## Контекст

На Wix оплата идёт через Wix Payments, цены занятий и товаров владелец правит в админке и должен продолжать править там же. Сайт сначала работает на тестовом аккаунте Stripe, потом переезжает на аккаунт клиента.

## Решение

Оплата — страница Stripe Checkout (hosted), `mode: payment`. Строки заказа передаются через `line_items[].price_data`: цена берётся из CMS в момент оформления, а `product` — это Stripe Product, который создаётся лениво при первой покупке и находится по метаданным `cms_kind`, `cms_id`, `path`. Адрес доставки не запрашивается, телефон запрашивается, `expires_at` = now + 30 минут, `metadata.orderId` связывает сессию с нашим заказом.

## Почему

- Цены, заведённые в Stripe заранее (Price на каждый товар и каждую дату). Отвергнуто: у цены две копии, и каждая правка в админке потребует синхронизации. Объекты Stripe прикреплены к аккаунту, поэтому переезд на аккаунт клиента превратился бы в перенос каталога.
- Собственная форма карты (Elements). Отвергнуто: приём карт, 3DS, Apple Pay / Google Pay / Link и промокоды пришлось бы строить и сопровождать самим. Для задачи этапа это объём без выгоды. Embedded Checkout остаётся вариантом на потом: он работает на том же API.
- `price_data` оставляет источником цены админку, а Stripe получает её на момент оформления.
- 30 минут — минимальный срок жизни сессии Checkout, который допускает Stripe. Срок удержания мест выбран равным ему (см. 0002).

## Последствия

- Покупатель уходит на страницу Stripe: вёрстка платёжного шага не наша, подгонять её под дизайн сайта нельзя.
- В Stripe нет каталога цен: отчёты по продуктам строятся по Stripe Products, найденным через метаданные.
- Первая покупка нового товара или даты тратит лишний вызов API на создание Product.
- Брошенная оплата держит места целых 30 минут: короче срок Stripe не даёт.
- Налоговые ставки тоже приходят строкой Checkout (см. 0003).
