# 0006. Привязка к аккаунту Stripe только переменными окружения

## Контекст

Сайт собирается и проверяется на тестовом аккаунте исполнителя, а работать будет на аккаунте клиента. Переезд должен быть сменой ключей и настроек, без правки кода и базы.

## Решение

В коде и в базе нет id объектов Stripe, кроме двух мест: `plans.stripePriceId` и ссылок на уже созданные платежи в заказах. Продукты товаров и сессий и `tax_rates` создаются лениво и ищутся по метаданным (`cms_kind`, `cms_id`, `path`; `code`, `province`, `percentage`). Аккаунт задают `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` и `CRON_SECRET`. Скрипт `npm run stripe:setup` в текущем аккаунте создаёт продукты и месячные цены тарифов, записывает их id в `plans.stripePriceId` и с флагом `--webhook <url>` заводит endpoint вебхука, печатая его signing secret. Ссылку на портал клиента вставляют в настройки сайта. Ссылка на платёж в админке строится по префиксу ключа (`sk_test_` ведёт в `/test/`).

## Почему

- Хранить id Product и Price в CMS при каждой покупке или сиде. Отвергнуто: после переезда все id были бы чужими, пришлось бы переписывать базу и следить за расхождением.
- Прописать id в код. Отвергнуто: id привязаны к аккаунту, а правка кода ради смены аккаунта — ровно то, чего мы избегаем.
- Ручное создание цен абонементов в панели клиента. Отвергнуто: скрипт повторяем и одинаково работает на тестовом аккаунте и у клиента, браузерный доступ к панели не нужен.
- Исключения оправданы: Price подписки должен быть стабильным (см. 0004), поэтому его id — единственное, что записывается в CMS; платёж в заказе — история, а не ссылка для работы.

## Последствия

- Старые заказы остаются с id платежей прежнего аккаунта: их ссылки «Open in Stripe» откроются только под старым ключом.
- Поиск по метаданным выполняется при первой покупке каждого товара; при двух одновременных первых заказах возможен дубль Product.
- Переезд включает ручные шаги: смена трёх переменных, запуск `stripe:setup`, ссылка портала, проверка покупкой тестовой картой.
- Ключи живут только в `.env.development.local` и переменных Vercel, в репозитории и документации их значений нет.
